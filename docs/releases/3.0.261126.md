A bug-fix release for the 3.0 code. A model that uses a type of another domain - an `@abstract` base kept in
`common`, an enum, a DTO - now compiles in every mode, and the contract tests work under Spring Session.

### Bug fixes

- **A type of another domain is named simply and imported from its domain** (#331). A model's type names are unique
  across domains, and a type is used where it is declared, as 2.x did; a copy is never written. Generated on
  `release/3.0` in every combination (JPA, MyBatis, MongoDB; Java and Kotlin; layered, ddd, hexagonal) and compiled,
  these did not compile and now do:
  - the `@extend` parent of another domain, not imported by the MyBatis and MongoDB entities;
  - `@extend(common:AuditEntity)`, refused under MyBatis as table inheritance and written as `extends common:AuditEntity`
    under JPA - a `domain:Name` is now read as the simple name everywhere (fields, generics, DTO parents, `@template`);
  - a port interface, the MyBatis port adapter and mapper, and the Spring HTTP port, which did not import another
    domain's DTOs and enums they name;
  - a command parameter typed with another domain's enum, in the behaviour class.

  A DTO `@template` of another domain's entity no longer writes a copy of that entity's key DTO into the using domain
  (the 3.0 output; the 2.x-compatible output keeps what 2.x writes): delete the unused copy left from an earlier build.
  The warning for a type name two domains declare now says to rename one.
- **`testCode: "contract"` under Spring Session** (#295). The support class kept only the container's session after
  the generated sign-in and dropped the answer's cookies; under Spring Session the signed-in session is the one its
  `SESSION` cookie names, so every later request was a visitor and the `@access` tests aborted. `signIn()` and
  `signIn(role)` now keep the cookies and `perform` / `sentBy` send them; where the container keeps the sessions nothing
  changes. A support class you edited elsewhere (`request(...)`, `newSignInRow`) takes the new lines over by the merge;
  one whose own lines meet them (your own cookie fix) is kept, and the run says where to take the change over by hand.
- **A command parameter that fills a reference is sent a row of the test's** (#295). `move(boardId: long!)` was sent a
  fixed `1`, which names no row of the test's (404); it is now sent the key of a row the test makes first.

### Compatibility checks

- A model that uses none of these generates the same, except the key DTO copy named above. The 2.x-compatible output
  is unchanged: `elcoreRulesCheck -Pstrict` reports 0 DIFF and `elcoreTreeCheck` 0 differ / 0 missing / 0 extra.
