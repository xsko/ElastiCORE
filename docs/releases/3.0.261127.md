This release adds two things to the 3.0 line, neither of which changes an existing project: a nested DTO that can
carry a referenced row for the holder's readers (an opt-in), and a CycloneDX SBOM published with every artifact.

### New features

- **`config: nestedRows: readers` - a referenced row for whoever may read the holder** (#321; built on
  https://github.com/xsko/ElastiCORE/pull/330 by its contributor). A nested DTO (`product: ProductDTO` in a
  `CoverageDTO`) was left out whenever the referenced entity was not `public` - also where it was safe, with a
  `Coverage` and its `Product` both read at `read=user` or `read=MANAGER` - and every screen fetched the row again.
  With the new env.yml setting, per domain:
  ```yaml
  elasticore:
    config:
      nestedRows: readers     # default: public
  ```
  the row is carried when everyone who passes the holder's `read` also passes the referenced entity's `read`. It is in
  what a read answers (read one, search, export); create, update, commands, `me()` and sign-in, which check other
  levels, answer it as `null` (the identity field stays), so nobody gets a row they may not read; a nested DTO sent in
  a create or update never writes the referenced row. The DTO, its TypeScript type and the sortable paths gain the
  field. **The default, `public`, generates what 3.0.261126 generates, byte for byte**; the warning of a row the
  setting would carry now names it. In 3.1 `readers` becomes the default.

### Build and release

- **A CycloneDX SBOM with every artifact.** elasticore-base, elasticore-springboot3, elasticore-springboot4 and the
  Gradle plugin are published with `<artifactId>-<version>-cyclonedx.json` (CycloneDX 1.6) and its signature, next to
  each jar on Maven Central and on the GitHub release. It lists the artifact's runtime dependencies with hashes,
  licenses, purls, producers (or `unknown` where no POM names one), the dependency graph, its author and the build
  lifecycle - the elements of CISA's 2026 minimum SBOM elements that a build can give. The libraries' dependencies
  are also submitted to GitHub's dependency graph, so Dependabot sees them.

### Compatibility checks

- A model without `nestedRows: readers` generates the same as 3.0.261126 (compared file by file in ten generations);
  the 2.x-compatible output is unchanged: `elcoreRulesCheck -Pstrict` reports 0 DIFF and `elcoreTreeCheck`
  0 differ / 0 missing / 0 extra. POMs and Gradle module metadata are unchanged; the SBOM is an added file.
