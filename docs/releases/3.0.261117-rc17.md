The seventeenth release candidate of 3.0: findings from projects moving from 2.x and from the issues filed on the
3.0 code - searches, DTOs, DBMS ports, API errors, lifecycle commands and the 2.x generator.

### Bug fixes

- **A like search looks for the value as written** (#159).
  - In a contains, prefix or suffix search, the caller's `%` and `_` are characters, escaped with `!`: `100%` finds
    `100%`, not every row with 100 in it.
  - This applies to the 3.0 JPA code (Java, Kotlin) and the MyBatis search.
  - `auto` keeps the `%` as a pattern, as documented.
- **A DTO carries a list of values** (#158).
  - `List<Long>`, `List<String>` and the DSL's `List<long>` were left out of the DTO without a word. They are now a
    `List` of the value's type (`number[]` / `string[]` in TypeScript).
  - `long[]`, `double[]` and `boolean[]` are arrays beside `int[]`.
  - A list of an unknown type is a warning. The 2.x-compatible output still leaves the list out, and says so.
- **`@expose(pageSize=N, methods="...")`** (#160).
  - A page size beside `methods` was lost: the search paged by 20.
  - The named form is the one to write. `@expose(50)` still pages by 50.
- **`@expose(methods)` serves one of a pair** (#172).
  - New names `updateOne`, `updateBatch`, `deleteOne` and `deleteBatch`.
  - `schema=false` leaves out `GET /schema/info`.
  - A narrowed controller keeps no unused import.
- **A lifecycle command keeps its parameter** (#170).
  - A command parameter named as a field of the entity is stored by the generated move.
  - Any other parameter is a warning: it was dropped without a word.
- **A search DTO's string field has its length as `@Size`** (#169), after the project's own rules.
- **DBMS ports** (#164, #165).
  - A method whose only parameter is a list of values binds it by name (`IN (:ids)` found nothing).
  - An enum field of a result row is read as the enum: by `fromCode`, by the name, or by the ordinal.
- **The generated API errors answer a CHECK violation 400 `check`** (#167).
  - It was 409 `conflict`, and on SQL Server 409 `referenced`.
  - A never-edited `XxxApiErrors` is regenerated with it.
- **`@forceupdate` on an entity's relation** (#166): the 2.x generator's mapper compiles, and matches the 2.x-compatible
  code.
- **Warnings that were wrong where nothing was wrong.**
  - An `@table` that starts with `table.prefix` is said once, by `elcoreMigrationCheck`, not on every build.
  - The reserved-word warning names only the databases `ddl.databases` writes for (#168).
- **The Ossie export does not declare an integer division portable** (#157). OSSIE_SQL_2026's `/` is true division.

### Documentation

- The README's Apache Ossie section: ready for BI tools from day one.
- The dev guide says what a `Q` condition's third argument (`chkEmpty`) does, and not to use it for a condition that
  must hold.

### Compatibility checks

- The 2.x-compatible output is unchanged for a model that uses none of these:
  - `elcoreRulesCheck -Pstrict` reports 158 MATCH / 0 DIFF / 2 ACCEPTED;
  - `elcoreTreeCheck` reports 0 differ / 0 missing / 0 extra.
- The 2.x generator changes only for output that did not compile (#166).
