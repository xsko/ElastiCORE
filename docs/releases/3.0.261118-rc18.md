The eighteenth release candidate of 3.0: what applications on the 3.0 code wrote by hand - a count of the rows that
point to a row, what becomes of them when it is deleted, one search box over several fields - is said in the DSL,
and a CI step checks the DSL and the generated files.

### New features

- **`@count(Comment.post[, status == VISIBLE])`** (#179).
  - A count kept on a row of the rows that point to it: `commentCount: long @count(Comment.post, status == VISIBLE)`.
  - Each write of a counted row through the generated service touches the count; it is counted again once, just
    before the commit, with the counting row locked. A soft-deleted row is not counted.
  - The field is read-only to requests and starts at 0. Java and Kotlin on JPA; MyBatis and the 2.x-compatible output
    stop the build.
- **`@onDelete(cascade | restrict | setNull)`** on a reference (#180).
  - Written on the side that points: `post: Post @onDelete(cascade)`.
  - Deleting the row - by key, in a batch, or by search - first refuses (409 `restricted`), clears, or deletes the
    rows that point to it, in the same transaction. Rows pointing to each other are refused with 409 `cycle`.
  - A project that keeps its own copy of `v3/service.tmpl` or `kt/service.tmpl` needs the two new slots in its
    delete-by-search line.
- **`@search(words:title, body, author.nickname)`**: one search box over several fields (#182).
  - Every word has to be found, each in any of the fields; a to-one path is joined, a collection is asked with
    EXISTS. The 3.0 JPA code, Java and Kotlin.
- **`./gradlew elcoreValidate`**: a CI step.
  - It fails when the DSL does not pass, or a generated file in git is not what the DSL generates now, and writes
    nothing but `build/elasticore/validate.md`. `-Pstrict` fails on a DSL warning too.
  - With `output = 'v2'` it runs 2.x's `elcore -Pmode=valid`.
- **`referenceColumn: field`** (#171): a reference by id is stored in `<field>_id` (`author: Member` -> `author_id`).
- **TypeScript client: `configureApi({ baseUrl, fetch, init })` and a per-call `RequestInit`** (#176): credentials,
  headers, your own `fetch`, an `AbortSignal`. Existing callers compile unchanged.

### Changes

- **A condition compares with `==`, `!=`, `>=` and `<=`.** `@invariant(totalAmount >= 0, '...')` was dropped without a
  word; it is now generated, and a write that breaks it is refused (422).
- **The Ossie export carries an enum field's codes as data** (#174): `"codes": {"NONE": "Disabled", ...}` beside the
  enum's name. Every exported enum field changes in `semantic_model.yml`.

### Bug fixes

- **`@audited` on H2 and SQL Server.** A write failed with `NULL not allowed for column "REV"`: the DDL now makes
  `revinfo.rev` an identity column there, as Hibernate expects. PostgreSQL and Oracle are unchanged. A Flyway history
  made before says to make the table again by hand on H2 and SQL Server.

### Documentation

- The pet store uses `@count` and `@onDelete`; its guide page, the README, the tour and getting started say what is
  new, and getting started puts `elcoreValidate` in CI.

### Compatibility checks

- A model that uses none of these generates the same, and the 2.x-compatible output is unchanged:
  `elcoreRulesCheck -Pstrict` reports 0 DIFF and `elcoreTreeCheck` 0 differ / 0 missing / 0 extra.
