The first patch release of 3.0: two security fixes - a deleted member's session over MongoDB, and error bodies that
echoed the database's text - bug fixes to search, repositories, the generated-file merge and the html cleaner, a
failed 2.x generation that now fails the build, and one opt-in feature - `@sensitive` keeps a field out of the Apache
Ossie export.

### New features

- **`@sensitive` leaves a field out of the Apache Ossie semantic model** (#184).
  - A field marked `@sensitive` - an email, a sign-in provider's account id, an API key - is left out of its dataset
    and recorded in `omitted_columns`, as a `@password` column is, so a BI or AI tool reading the model is not told it
    may select it. The model's `ai_context` says such columns are left out (only when one is marked).
  - On an `@Embedded` value it leaves out all the value's columns; on a reference, its join column and its
    relationship. A reference that joins on a `@sensitive` field is not exported as a relationship either, with a
    warning, and a metric over it is refused. On an `@id` or a collection it is ignored with an `[ossie]` warning.
  - Nothing else reads it: DTOs, responses, access rules, DDL, the 2.x code and the Kotlin/TypeScript output are the
    same with it and without. A model without it exports byte for byte what it did.

### Changes

- **An enum value longer than its field stops `elcore3`, as it already stopped `elcore`.** `CANCELLED: CXL,Cancelled`
  with `code: string(2)` was only a warning in the 3.0 code, and the mistake surfaced as a failed insert at run time.
  Generation now runs to the end, then the build fails with `[elcore3] the model check failed (n) - fix these and
  build again:` and the finding - `[shop] enum OrderStatus.CANCELLED: field 'code' value 'CXL' (length 3) exceeds max
  length 2. Make field 'code' at least 3 characters long or shorten the value.` The message names the domain, and says
  so when the value is missing from the line and the constant's name stands in. `-PlistRules` ends non-zero on such a
  model. Every other DSL warning stays a warning.
- **A failed 2.x generation ends non-zero, with its cause.** The 2.x generator (`./gradlew elcore`, `output = 'v2'`,
  `-Pv2`) printed an exception and ended 0, so the build went on to compile what was there. It now ends 1 with
  `[ERROR] ElastiCORE generation failed: <the exception>`; a model file that is not YAML (`[ERROR] LOAD ERROR ...`) and
  a source that could not be written (`[ERROR] not written: ...`) end it 1 too. `-Pmode=valid` fails on a model file
  it could not read. Generated code does not change; a 2.x project whose generation fails now fails its build.

### Security fixes

- **A member deleted under `@deleted` no longer keeps a working session over MongoDB.** In `mode: mongo` the
  service's `me()` read the signed-in document without the filter every other read applies, so after a member was
  deleted (by themselves or an administrator) the session they had went on: `GET /me` answered 200 with the deleted
  document, and `@signin(refresh=request)` kept the session instead of ending it. `me()` now leaves a deleted document
  out: `GET /me` answers 401, and with `@signin(refresh=request)` the session ends with the next request, which is a
  visitor's. JPA and MyBatis were not affected - their `findById` already leaves a deleted row out. Without
  `refresh=request` a session is not read again, in any store, so it keeps working until it expires; the build now
  says so for a `@signin` entity with `@deleted`, and how to end it.
- **A refusal of the database or MongoDB no longer echoes the driver's text.**
  - REST over MongoDB: a taken `@unique` value answered 409 with the driver's message as `detail` - the server
    address, the collection, the index and the value (an email, say). It is now `409` with `"code": "unique"` and
    `A unique value is already taken.`, the answer JPA and MyBatis already gave. The generated `ApiErrors` is a
    generate-once file: one you have not edited takes the change on the next build; an edited one takes it when it
    merges cleanly, otherwise the build reports it as kept (`KEPT(yours ...)`) and the `if (ex.getCause() != null)`
    branch of `duplicate(...)` is yours to add.
  - GraphQL, every store (JPA, MyBatis, MongoDB): the error's message was the exception's - for a unique violation
    over JPA the whole SQL statement with the duplicate value, for a stale version the ORM's own text. A duplicate
    key, an integrity violation or a stale version now says its kind - `code` `unique`, `referenced`, `required`,
    `check`, `conflict` or `stale` in the extensions, with the same sentence as REST - and status 409 as before.
    Fixed in both runtime libraries, `elasticore-springboot3` and `elasticore-springboot4`.

### Bug fixes

- **A Kotlin `@readonly` service has no write methods**, as the Java one. The Kotlin service (JPA) kept `save`,
  `update`, `batchUpdate`, `delete`, `deleteById` and `updateBySpecification` - the generator read a method's name
  only from a Java `public`/`protected` signature, not from Kotlin's `open fun`. The controller already had no write
  endpoint, so nothing changed over HTTP; the service no longer offers the application's own code a way to write a
  read-only entity. The same for a service method named by `@restExclude`. The generated Kotlin service test leaves
  out the tests of the methods the service does not have. Upgrading: if your own Kotlin code overrides or calls one of
  those methods of a `@readonly` (or `@restExclude`) entity's service - in the extension service `XService.kt`, or in
  a generated service test you edited and the build kept - it no longer compiles; remove the override or the call.
- **Search on a list of values against one column.** A search DTO's `status: List<OrderStatus> @search(in)` - the DSL
  guide's own example - or `@search(eq)`, where the entity's `status` is one enum, was joined as if it were a
  collection by every JPA mapper: the query failed at run time with `... is not joinable`, and the 3.0 Java mapper did
  not compile. It is now the column's `in` (`r.get("status").in(status)`) or equality (`c.equal(r.get("status"),statusItem)`), in the 3.0
  Java and Kotlin code and in the 2.x generator. A list field that is a collection of the entity still joins.
- **A repository method without `query:` is a Spring Data derived query.** The 2.x generator stopped on it with a
  `NullPointerException` and wrote no repository, in every version from 2.0 on; it now declares the method as it is
  named, without `@Query` (JPA and MongoDB).
- **A derived query without `return:` answers by its name instead of `void`**, in every generator: `find`/`read`/`get`/
  `query`/`search`/`stream`...`By` a `List<Entity>` (`Page<Entity>` with `pageable: true`), `countBy` a `long`,
  `existsBy` a `boolean`; `deleteBy`/`removeBy` and any other name stay `void`. A `void` find compiled and failed when
  it was called.
- **Generated-file merge: a layout-only difference is no conflict** (#230). When you and the DSL make the same change
  to a generated file and the two differ only in blank lines or trailing spaces, it merges and keeps your text; a file
  is no longer kept out of every later DSL change for it. Indentation and spaces inside a line still count. A kept
  file's note now says at which line each conflict starts.
- **A key DTO imports only what its key fields use** (#231), in the 3.0 Java and Kotlin DTOs, so an unused-import
  check no longer flags the enums and `java.util.List` of the fields it leaves out.
- **`Html.clean` keeps relative links** (#217), in both runtime libraries: `<img src="/api/files/3">` keeps its `src` under `@safe(relaxed)`, and
  `/posts/7` or `#top` its `href` under both safelists. `javascript:`, `vbscript:`, `data:` and links a browser reads
  as another host's are still removed. Under `basic`, `rel="nofollow"` is put on links to another host only.
- **Overriding a lifecycle command in the behavior class silences the "does not keep" warning** (#229), as the
  warning advises. Generated code does not change.
- **Warnings that say what to do:**
  - A layered build of a domain with `referenceColumn: short` or `field` says the setting is read by `ddd` and
    `hexagonal` only (`elcoreValidate -Pstrict` then fails until the setting is removed).
  - In layered, `@owner(customerId)` through `customer: Customer @ManyToOne` names no field; the warning now says the
    two lines to write instead.
  - A `@searchable` DTO of an entity in another domain is searched by nothing (no `toSpec` is written for it); the 3.0
    code now says so and where to declare it.
  - The layered build's "not enforced" warning names `architecture = 'ddd'`, the documented value, instead of
    `'domain-model'`.
