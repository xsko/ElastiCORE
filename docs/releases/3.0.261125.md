A bug-fix release for the 3.0 code. The fixes that change what runs:
- the TypeScript client no longer offers commands the server does not serve (they answered 404)
- a migration that gives an index name to another table no longer fails on PostgreSQL, Oracle and H2
- a search DTO's list is bounded by `@maxsize`, so one request can no longer bind any number of values into `in (...)`

The rest are build-time warnings for models that did not work as written, and a refusal message that kept its `{0}`.

### Bug fixes

- **A migration that gives an index name to another table drops the old index first** (#329). When a table's name
  changed (a `table.prefix` added, `@table` changed, the entity renamed), the migration made the new table's
  `@Index(name=...)` while the old table - kept for review, its `DROP TABLE` commented out - still held an index of that
  name. PostgreSQL, Oracle and H2 hold an index name once per schema, so Flyway stopped and the application did not
  start. The old index is now dropped first, as written (it drops an index, not rows); the old table's drop still waits
  for review. An index moved from one table to another is dropped once, before it is made again.
- **Commands the server does not serve are not offered by the TypeScript client.** The client wrote a function per
  `commands:` entry (`close(id)` posting to `/{id}/close`) for every entity with one key, while the server serves a
  command only for a root with a behaviour class - a root that is not `@editable`, with `architecture = 'ddd'` or
  `'hexagonal'`. In layered, and for an `@editable` root, those functions answered 404; they are gone. A layered build
  declaring `commands:` now says they are not served.
- **A search DTO's list is bounded by `@minsize` / `@maxsize`** (#324). `postIds: List<Long> @search(in) @maxsize(200)`
  on a `@searchable` DTO got no `@Size`, so a search could bind any number of values into one `in (...)`. It now gets
  `@Size(max=200)` (with the message, when one is given), so a longer list is a 400 before the query is built. Java and
  Kotlin. The annotation guide also says that an empty list, like one not sent, is no condition.
- **`InvariantViolationException(code, message, args)` fills its `{0}`** (#325), as `BadRequestException`,
  `ConflictException`, `NotFoundException`, `ForbiddenException` and `NotSignedInException` do: a 422 whose code the
  application's messages do not translate answered `"detail": "{0} is your only way ..."`. A message without a
  placeholder is kept as written, so the generated checks' sentences keep their quotes.
- **An `@Index` naming a column its table does not have is a build warning** (#323), with the columns the table has
  (and the reference's column when one ends with the name: `product_code (perhaps product_product_code)`). Before, the
  build passed and the table was missing at run time. JPA always, MyBatis when it writes a DDL. Nothing generated
  changes.
- **`states:` in layered: the warning says what adding `ddd-state` gives** (#320) - the initial state only - and names
  what the lifecycle needs: a root that is not `@editable`, with `architecture = 'ddd'` or `'hexagonal'`. A lifecycle
  whose commands are not written is said too, in ddd and hexagonal for an `@editable` root as well.

### Documentation

- `@table` now says that `table.prefix` goes before its name too, as in 2.x (`@table(PL_QUOT)` with `prefix: jp_` is
  `jp_pl_quot`); for names used exactly as written, leave the prefix out.

### Compatibility checks

- A model that uses none of these generates the same; a TypeScript client of a layered or `@editable` root with
  `commands:` loses the command functions that could only fail. The 2.x-compatible output is unchanged:
  `elcoreRulesCheck -Pstrict` reports 0 DIFF and `elcoreTreeCheck` 0 differ / 0 missing / 0 extra.
