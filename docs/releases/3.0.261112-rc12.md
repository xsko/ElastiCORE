The twelfth release candidate of 3.0: an abstract `@Entity` root (`@abstract(entity)`) with `@deleted`, the Oracle 23
boolean, the Ossie export on core spec `0.3.0.dev0`, the database ports' last MyBatis limits removed, and mistakes the
compiler or the database found now said when the code is generated.

### New features

- **`meta: entity @abstract(entity)` - an abstract `@Entity`, the root of a hierarchy read through one repository and
  one service.** The abstract class gets `@Entity` and `@Table`, keeps the model's `@jpa:Inheritance` (`JOINED` or
  `TABLE_PER_CLASS`), and has a repository, a Q class and a service that reads, searches, updates and deletes - Java and
  Kotlin. It has no create (no POST, no `toEntity`, no create in the TypeScript client). Plain `@abstract` stays a
  mapped superclass. A root without a key, or with another inheritance strategy, stops the build. The project DDL of
  any abstract `@Entity` under `TABLE_PER_CLASS` - hand-written or 2.x - no longer has a table for it or foreign keys to
  it, as Hibernate makes none.
- **`@deleted` on the root of an `@abstract(entity)` hierarchy keeps the rows of every subclass.** Under `JOINED` the
  column is in the root's table and the root's statement writes the time; under `TABLE_PER_CLASS` each subclass's table
  has it. The root's repository and the search leave deleted rows out. `@deleted` on a subclass only stops the build.
- **`ddl { oracleVersion = 23 }`**: on Oracle 23 a boolean is a `BOOLEAN` column, as Hibernate maps it there, so
  `ddl-auto=validate` passes. Unset, or below 23, it is `NUMBER(1)` as before. Setting it over tables already there
  gives an Oracle migration that moves each boolean column's values, held for review.

### Changes

- **The Ossie export follows core spec `0.3.0.dev0`.** It writes `version: 0.3.0.dev0` (Ossie's schema accepts only its
  own version, and there is no 0.2.0). The ELASTICORE extensions are `nonportable_extensions`, and their `data` is an
  object instead of a JSON string (apache/ossie#522). A metric over one entity is written in that entity's dataset,
  where Ossie's relational interface exposes it as a measure (`revenue` is now `PurchaseOrder.revenue`); a metric over
  several entities stays at the model root. A dataset's `source` carries the table's schema (`@schema`, `tableSchema`).
  A JOINED subclass's dataset holds the columns of its own table. Only a project that names the `ossie-export` rule set
  sees a new `semantic_model.yml`. A consumer that read `data` as a JSON string now gets an object.
- **What could not compile or be created is said when the code is generated (v3 JPA).** An exposed entity whose
  composite key holds a relation stops the build with what to write instead (its controller did not compile). A table
  or column named with a word Oracle, PostgreSQL or SQL Server reserves (`order`, `group`) is warned about, as under
  MyBatis. A type the DSL does not have (`uuid`, `short`, `char`, `offsetdatetime`) is warned about with what to write.
- **A DTO field that declares a referenced root's key under a name of its own** (DDD reference by id) is warned about
  instead of being dropped in silence.

### Bug fixes

- MyBatis database ports - the limits the guides listed are gone:
  - `/* if */` blocks nest: each `/* if-end */` closes the innermost block, and a conditional line inside a block is
    read. The port runtime reads them the same way.
  - A port method may take a `Pageable`: the interface imports it, and its page and `Sort` are the call's (the runtime
    proxy reads its page too).
  - The call's sort goes first in the SQL's own `ORDER BY`, as in the runtime, and an `ORDER BY` inside `/* if: */`
    still pages on SQL Server when its condition is false.
  - A `Map` row has every column, a NULL one as null (`PortRowColumns`, applied by the MyBatis Spring Boot starter).
  - The aggregate's delete locks the row with `SELECT ... FOR UPDATE` (`UPDLOCK` on SQL Server) instead of
    `UPDATE ... SET v = v`, which MySQL with `useAffectedRows=true` read as a stale copy.
- `rating: double @min(0.5) @max(5.0)`: a bound with a fraction on a `double` or `float` is a `@DecimalMin` /
  `@DecimalMax`, so the DTO compiles. The 2.x-compatible output is unchanged.
- The 2.x generator wrote the `@min` value into the `@DecimalMax` of a `bigdecimal`, refusing every value above the
  minimum. It now writes the `@max` value.
- Project DDL: `elcoreDdl` run before the code is generated stops and names the entities it could not read, instead of
  writing tables without columns; under `mapping: xml` a `money` or `quantity` column is a decimal or an integer again,
  not text; an unnamed sequence is named after the root's table, as Hibernate names it.

### Compatibility checks

- The 2.x-compatible output is unchanged for a model that uses none of the new features. `elcoreRulesCheck -Pstrict`
  reports 158 MATCH / 0 DIFF / 2 ACCEPTED, and `elcoreTreeCheck` 0 differ / 0 missing / 0 extra.
