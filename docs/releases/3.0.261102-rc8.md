The eighth release candidate of 3.0: English guides, `supportAI` removed, and fixes.

### Changes

- **The guides a project receives are in English.** Every generation copies the nine guides into `blueprint/` in
  English, under the same file names as before. A team that prefers Korean sets `elasticore { guides = 'ko' }`
  (`-Delasticore.guides=ko` without the plugin). A language the guides are not written in gives a warning and the
  English guides. Generated code is unchanged.
- **`supportAI` is removed.** The setting is ignored, and each domain that still sets it gets one line:
  `[ElastiCORE] domain '<name>': supportAI was removed and is ignored`. The service is generated without the Spring AI
  `@Tool` methods. Upgrading a project that used it:
  - On 3.0 code (`elcore3`), a `XxxService` nobody edited is written again without the tools; an edited one loses the
    tool methods and keeps your edits.
  - On 2.x code (`output = 'v2'`), the service is written once and never again, so it keeps its tools: delete the
    `@Tool` methods (or the file, to have it written again) before you drop the Spring AI dependency.
  - Take `supportAI` out of `env.yml`. The env guide (chapter 3) and the migration guide (item 5) say so.

### Bug fixes

- **`checkEmpty` keeps a condition that takes no value.** `Q.Order.deletedAt(Op.IS_NULL, null, true)` added no
  condition, and the query returned every row. `IS_NULL` and `IS_NOT_NULL` now always write their condition; the other
  operators still drop an empty value. Generated search code was not affected.
- **A build with `generateBeforeCompile = false` no longer runs `elcoreDdl` before its resources.** With
  `output = 'v2'` and a `ddl` block, every `build`, `test` or `bootRun` ran `elcoreDdl`, which loads the model and
  fetched a remote diagram (`resource:`) again. The DDL now comes with `elcore` only, when the build does not generate
  before compiling.
- **The warning that Oracle has no `TEXT` is given only for a schema written for Oracle.** A project writing its schema
  for other databases got one line for every `text` field.

### Compatibility checks

- The 2.x-compatible output is unchanged. `elcoreRulesCheck -Pstrict` reports 157 MATCH / 0 DIFF / 2 ACCEPTED, and
  `elcoreTreeCheck` reports 0 differ / 0 missing / 0 extra.
