The sixth release candidate of 3.0.

### New features

- **DDD and hexagonal over MyBatis.** `architecture = 'ddd'` or `'hexagonal'` with `mode: mybatis` used to stop the build ("MyBatis code is layered"). It now generates the domain model and the hexagon over MyBatis, Java only, Spring Boot 3 and 4.
  - The bundles `ddd-mybatis-springboot` and `hexagonal-mybatis-springboot` are chosen by the build's `architecture` and the domain's `mode`. A domain's `publisher.rules` that names `ddd-springboot`, `hexagonal-springboot` or `jpa-springboot-v3` is read as the MyBatis bundle.
  - What JPA did for an aggregate by itself, a generated `<Root>RepositoryAdapter` does:
    - It tells a new row by its missing version or key.
    - An update compares and counts up the version, of the root and of every member, and answers 409 when the copy is stale.
    - Member collections are compared with the stored rows. Gone members are deleted, kept ones updated with their keys, new ones inserted.
    - A to-one member (`@OneToOne @cascade`) is written before its root, and the member it replaced is deleted.
    - `delete()` refuses a stale copy before it deletes anything. A derived `deleteBy...` of a root deletes row by row, so delete guards and members run as with Spring Data JPA.
    - A row read again in its transaction keeps what changed in memory.
  - Members the model makes (`@cascade`, a root's `@OneToMany(mappedBy)`) are written by their root, as `@aggregate` members are.
  - The JPA callbacks (`@PrePersist`, `@PreUpdate`, `@PreRemove`, `@PostLoad`, `@PostPersist`) and `@DomainEvents` become the root's `io.elasticore.springboot3.domain.Lifecycle`. The adapter calls them at the same moments and publishes the events after the save.
  - Audit stamps, including the user from `AuditorAware`, are written for the root and its members. References are found through `Lookup.Source`; a type no adapter serves, such as a root of a JPA domain, falls back to the application's `EntityManager`.
  - The application service takes ports only, and the domain names no JPA or Spring Data type. The outbox runs on a MyBatis mapper with each database's row lock.
  - New sample: `elasticore-template-ddd-mybatis`, the DDD sample's model and all its tests on MyBatis. CI runs its database tests on Oracle, PostgreSQL and SQL Server.
- **Database ports of a MyBatis domain are a MyBatis mapper and an adapter.** The SQL stays as written in the DSL and is visible in the mapper XML. `:name` becomes `#{name}`, `/* if:name */` lines and blocks become `<if>`, and pages get a count statement. The runtime proxy steps aside for these ports. A JEXL condition in a port is refused with the reason.
- **More of the model over MyBatis, in every architecture:**
  - `@abstract` parents' fields become the row's columns.
  - `@CreatedBy` and `@LastModifiedBy` are filled from `AuditorAware`.
  - The inverse side of a one-to-one is read by joining the other row.
  - `repository.yml` queries become mapper statements: derived names and `nativeQuery` SQL. Before, they were silently left out of MyBatis domains.
- **`JdbcDbmsGateway`.** Database ports run in an application without JPA.

### Changes

- **A page's count from a database port leaves out the SQL's last `ORDER BY`.** This holds for JPA projects too. SQL Server refuses an `ORDER BY` inside a derived table; other databases give the same count as before. An `ORDER BY` followed by `LIMIT`, `OFFSET` or `FETCH` is kept, so only those rows are counted.
- In a MyBatis domain, picking a `ddd-*` or `hex-*` rule set in `publisher.rules` without `mybatis-ddd` stops the build with the reason. Without it, the JPA callbacks would stay as dead annotations and invariants would not run.
- Over MyBatis:
  - `@audited` and JPQL queries are refused with the reason.
  - In a layered domain, a root's to-one member without its own service is refused. Before, its key was silently written as null.

### Bug fixes

- MyBatis derived queries:
  - `Containing`, `StartingWith` and `EndingWith` match `%` and `_` in the value as written.
  - An empty list given to `In` or `NotIn` no longer causes an SQL error.
  - `findAllByOrderBy...` builds.
- Ports over MyBatis:
  - A page of SQL without `ORDER BY` works on SQL Server.
  - A list of single values reads NULL as null. Before, a NULL column could be skipped and the next column returned.
  - A row whose columns are all NULL no longer fails.
  - `void` methods are supported.
- `biginteger` is `NUMERIC(38,0)` in MyBatis schemas. Before, BIGINT overflowed on large values.
- MyBatis reads and writes no longer fail after a Spring Boot DevTools restart.

### Documentation

- The env guide (2.3) covers DDD and hexagonal over MyBatis:
  - what the adapter does;
  - derived queries;
  - port SQL rules: NULL values, `void`, how a page's count treats `ORDER BY`, the SQL Server fallback;
  - what is refused.
- The guide also lists what is not supported yet:
  - a `Pageable` parameter on a port method;
  - nested `/* if */` blocks;
  - an `ORDER BY` inside `/* if */` in a paged port on SQL Server.

### Compatibility checks

- The 2.x-compatible output is unchanged. `elcoreRulesCheck -Pstrict` reports 157 MATCH / 0 DIFF / 2 ACCEPTED, and `elcoreTreeCheck` reports 0 differ / 0 missing / 0 extra.
