The fifteenth release candidate of 3.0: a fix to the API errors order check added in rc14.

### Bug fixes

- **A generated `XxxApiErrors` that is already next to last is no longer flagged.** On rc14, `elcore3` and
  `elcoreMigrationCheck` warned on every build that an application advice answering every exception tied with the
  generated `XxxApiErrors`, even when that file was already `@Order(Ordered.LOWEST_PRECEDENCE - 1)`: the check read
  the words "in this class" in the generated comment as the class declaration and missed the `@Order` below it. The
  check now reads past comments. Only the warning was wrong; the generated code and its order are unchanged.

### Compatibility checks

- The generated code is the same as in rc14; only the build's check changed.
