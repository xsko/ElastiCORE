This release fixes four bugs on the 3.0 line. A project that does not hit them generates what 3.0.261127 generates,
except for the generated services' new handling of a refused write and the TypeScript client's imports, described below.

### Bug fixes

- **A `-- label` holding `=` is kept as written** (#345). A field's label such as
  `-- shortest period in months (1 = to the same day of the next month)` was read as `key=value` pairs and cut to a
  fragment (`day)`) in the entity, `schema.yml`, the DDL comment and the migration, without a warning. The text after
  `--` (and its ` | ` description) is now the label whatever characters it holds; a hand-written `@label(...)` reads as
  before.
- **The TypeScript client compiles under create-vite's React-TS settings** (#346). With `noUnusedParameters`,
  `verbatimModuleSyntax` and `erasableSyntaxOnly`, a client failed with up to 147 errors. Type-only imports are now
  `import type` (the `...Api.ts` files use the inline form, `import { request, type Page }`, which needs TypeScript
  4.5 or later), `validateX` names an unread parameter `_partial`, and `ApiError` declares its fields. Callers are
  unchanged. The repository's own client and the pet store's screens are now type-checked with those flags.
- **A refused write leaves no trace in what its transaction reads** (#344). When a generated update, update by
  condition or command was refused after the request was mapped onto the row (`beforeSave`, an invariant, a reference
  check), nothing was committed, but the changed object stayed in the transaction: a later read of the same row in
  that transaction (a batch, a caller that catches the refusal) returned the refused value. The generated services now
  discard the row and rethrow the same exception: JPA reads the entity again (`refresh`, `detach` where it cannot),
  MyBatis clears the transaction's session cache. MongoDB was not affected. **The generated services call new runtime
  classes, so upgrade `elasticore-springboot3` / `-springboot4` together with the plugin** (a project that copies the
  runtime with `runtimePackages` copies `RefusedWrite` too).
- **Contract tests: no test that can only abort for `create=none`, and rows made the project's way** (#358). For an
  entity whose API takes no create, the generated contract tests made their rows with a `POST` that is always
  refused, and aborted (221 of 942 in one application, with rows its own rules refuse). Now:
  - no test that needs such a row is written, and the summary says what to write;
  - each operation that is `none` for everyone gets a test that the signed-in administrator is refused (403);
  - an optional `protected Map<String, Object> new<Entity>Row()` in the support class - written by the project, never
    generated, like `newSignInRow(role)` - makes the rows the tests need the project's way, for any entity; the field
    tests then go through `PUT`.
  Without it and without `none`, the contract tests are unchanged.

### Compatibility checks

- The 2.x-compatible output is unchanged: `elcoreRulesCheck -Pstrict` reports 0 DIFF and `elcoreTreeCheck`
  0 differ / 0 missing / 0 extra.
