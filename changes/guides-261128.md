### Documentation (guides - what 3.0.261120 to 3.0.261128 changed)

#### The guides say what the releases from 3.0.261120 to 3.0.261128 changed, and no longer contradict them
- Why: a review of the guides against the history and the code of 3.0.261120 to 3.0.261128 found statements those
  releases made wrong and changes no guide named. A reader who learns from the guides alone met warnings, refusals and
  upgrade steps nothing told them about.
- Corrected (each checked against the code):
  - env guide: `@Mask`, `@encrypt` and MongoDB in Kotlin shipped in 3.0.261121, not "3.1"; the architecture test places
    the first segment of the `persistence` namespace too, and `adapter.out.*` with persistence (`ArchitectureTestSource.segments`);
    9-2's step for a branch from before the rename names step 1, where the base's side is picked.
  - rule guide: the Kotlin service leaves out what `@readonly` and `@restExclude` take away, as the Java one does
    (`MethodSections`, 3.0.261120); the generated `XxxApiErrors` answers a store's refusal by its kind (`unique`, `referenced`,
    `required`, `check`, `stale`), where the guide said such errors go to the user's handler.
  - annotation guide: a session without `refresh=request` lasts until it expires, not until the next sign-in; the `@readonly`
    service is Java and Kotlin (the AI extension service's tools, removed in 3.0, are gone from the sentence); the sort
    example lists what the pet store's `PurchaseOrderSrchDTO` generates; `methods=""` serves none of the six names.
  - dev guide: a refused write is undone with its caveats - a JPA row read again drops the transaction's earlier unflushed
    change to it, a row that cannot be read again may leave the transaction rollback-only, MongoDB needs nothing.
- Added: the upgrade steps of 3.0.261120 (Kotlin `@readonly`, `XxxApiErrors` over MongoDB), 3.0.261121 (wider
  architecture tests), 3.0.261126 (another domain's key DTO, the contract support class's cookies) and 3.0.261128
  (`RefusedWrite` in a `runtimePackages` copy, with `mybatis-spring` for MyBatis; the runtime raised with the plugin); the
  warnings of `@deleted` without `refresh=request`, layered `referenceColumn`, a `@searchable` DTO of another domain's
  entity, `@Mask` without a `MaskType`, layered `commands:` and `states:`, html among MongoDB members that hold each other,
  and the new advice of "the selected rules do not enforce" (env guide 7-1); `AccessPolicy.level` answering `null`; the rule
  helpers made public in 3.0.261123; `InvariantViolationException` filling `{0}`; `@minsize`/`@maxsize` on a search DTO's
  list; the Kotlin `@encrypt` refusal for a class and its parent; an index name another table takes; `ossie-export` named
  only under `ts:`; the CycloneDX SBOM (migration guide).
- Each warning and message is copied from the code that writes it (`RulesGenRunner`, `ServiceAccessRules`, `DddStateRules`,
  `HtmlRules`, `EncryptRules`, `MaskedFields`, `SchemaDiff`). Where the history and the code differ, the code was followed:
  the layered `referenceColumn` warning says "JPA's default join column, the field and the key's column", and the plugin
  has no `elasticoreVersion` setting (the history's 3.0.261128 entry names one; the plugin's own version decides).
- Checked: `GuideTranslationTest`, `GuideCoverageTest`, `GuideCoverageKoTest` and the other guide tests
  (`:elasticore-project:elasticore-base:test --tests "*Guide*"`). No code changed.
- Files: `elasticore-env-guide.md`, `elasticore-annotation-guide.md`, `elasticore-rule-guide.md`, `elasticore-dev-guide.md`,
  `elasticore-dsl-guide.md`, `elasticore-migration-guide.md` and their `ko/` copies.
